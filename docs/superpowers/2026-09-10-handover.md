### 3.3 长上下文侧的两个重要数（决定 attention 那条路值不值）

- **16K 的 attention 不是 1.6%，是 15.9% 步时（≈5.55 ms/step），且只用到 ≈9.0% HBM 峰值带宽**
  ⇒ 打满即 16K decode 从 28.56 → **33.35 tok/s（+16.8% 上限）**。计算脚本 `logs/a2b/calc_attn_headroom.js` `[实测]`。

  而 decode 期唯一随 ctx 线性涨的就是 attention ⇒ **这是未归因的异常，必须写进 #63 的验收问题** `[实测]`。

## 8. 判决与结论（不要重新研究这些）

1. **不需要手写 HIP attention（#21 关单）**：16K 只比 2K 慢 **14.4%**，"gfx906 长上下文必塌方"的前提对我们**不成立**
   （我们本来就在 64 段 split 上；fork 未修复路径的 0.238 tok/s 是另一套 generic 路径）。
2. **`TRITON_ATTN 必须`是几何相关，不是架构定律**（门谓词见 §4 末）。
   ⚠️ 改 `block_size`（例如 FP8 ⇒ 1568，或将来别的页对齐）**可能把 MFMA 支路重新打开** ⇒ 换配置后要重跑一次门谓词。
3. **MTP 投机解码**：两轮实测负收益（作者也报 8K 27.3→6.9）⇒ **不做**。
4. **custom all-reduce**：PCIe P2P 上 0 收益 + 图回放下有陈旧数据风险 ⇒ **不做**。
5. **BF16/FP8 权重**：gfx906 无矩阵指令 ⇒ **不做**。注意 **FP8 权重 ≠ FP8 KV**（后者可做，见结论 6）。
6. **FP8 KV 买到的不是翻倍**：+58.8%。机制可指到一行——`Setting attention block size to 1568 tokens to ensure
   that attention page size >= mamba page size`：fp8 只压 attention 半页，而 hybrid 对齐迫使块内 token 数翻倍，
   **GDN 状态页才是共同约束**。
7. **fork 与我们的 1.34×（44.74 vs 33.3 tok/s，同 TP2/27B AWQ）**：按桶只能落在占 60.2% 的 W4A16，
   可能只是一个编译宏之差（`q_gemm.cu` gfx906 重调）⇒ **但混淆项六个**（模型 3.6/3.8、torch 2.11+7.2.1 vs 我们更新的
   2.13+7.2.4、4×32 GiB vs 2×16 GB、100K vs 16K、128 token 预算 vs 我们 64、**他们通篇不记录 GPU 时钟**）。
   便宜动作 = **在我们这台机按他们协议复测**，再决定要不要花一次重编。
8. **"能不能搬"的判据 = 物件的载体在哪一层**：纯 python / 纯 Triton / 上游已合并 PR ⇒ 可取；
   `csrc/` 里的 C++/HIP ⇒ 不是"搬"，是**再走一遍构建通道**（等于再写一次 P2，2–3 天）。
9. **fork 里没有**：prefill、反量化→稠密 GEMM、启动工程、Tensile 补充、RCCL（grep 确认为零）`[实测]`
   ⇒ 这几项只能取 Z100 文章的**方法**，代码自建。
10. **Z100 的最大单项 = 大 M "先反量化 → 稠密 GEMM"**（作者 M=8192 3.22–3.58×、8K 模型级 +96.5%）。
    我们的 prefill 分母已经有了（§3.1），但**必须先跑 fp16 `torch.mm` 在 (8192,8192,5120) 的 TFLOPS 探针**
    （<15 ⇒ 先解决 rocBLAS 再立项）`[未决]`。这是本项目里唯一可能比 #20 全部阶段加起来还大的单项。
11. **换内核的验收判据**（P2 建立，已写进记忆）：**不要用逐 token 等值**。L1 = fp64 零自由度参考 + ULP；
    L2 = teacher-forced margin 归因 + top-N 包容；对照**不可重现**的 incumbent 时，
    "位相等 / ULP 尺 / 与 view 相比"三种都非法 ⇒ 只能用**它自身噪声定标的绝对带**。
12. **`FULL_DECODE_ONLY` 下 Python 计数器只看见 capture 期命中**（replay 不跑 Python）⇒
    分派证明只能比 launch **轮数**（off 1×64、on 3×64），不能比绝对计数。

## 11. 术语

| 术语 | 含义 |
|---|---|
| **gfx906** | GCN 5.1 架构（MI50 / Radeon Pro VII / Z100 / Vega 20），60 CU 档，**无 MFMA 矩阵指令** |

| **门 / 尺 / 标尺** | 门 = 通过/失败的判据；尺 = 用来量收益的分母（时钟/口径同源）；本项目每次混用尺都出过事故 |

| **G-P0 … G-P6** | P2 阶段的六道门（go/kill、生产 `.so`、路由、引擎 A/B、数值、交付态实测） |

| **incumbent** | 被替换的现产内核（本项目 = ExLlama 融合 W4A16 GEMV） |
