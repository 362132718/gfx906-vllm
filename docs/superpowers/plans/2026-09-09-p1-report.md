# #20-P1 报告（v2）：三个 wave64 W4A16 GEMV 原型 vs 现路径

> **v1 → v2 → v3 的变化**：
> ① 分母错用 ≈35.9 tok/s（P0.5 已证伪外推值）⇒ 统一为**交付态实测 32.4 tok/s（step = 30.86 ms）**；
> ② 字节地板被 load-only 探针证伪 ⇒ 换 load-only 为尺；
> ③ **v3（本轮）**：标量探针被证实 MLP 不足（4 B/lane 无展开，官方 dwordx4 指引点名的反模式）
> ⇒ 补 mlp（4 独立累加器）与 x4（dwordx4）两变体重测，**新尺 = 三者最优**（每形状 387–702 GB/s，
> 比标量高 18–59%）；另按评审完成 ULP 拆分（V3 vs incumbent 对 fp64 参考）与全部算术修正。

## 结论（先说答案）

1. **非 kill**：以三变体探针的最优值为尺（每形状 20.3–63.5 µs），原型在两族上优于现路径。
2. **窄 P2（选项 A）成立**：(5120,8192) 与 (5120,7168) 两族，V3 距新尺 1.92×/1.95×，
   incumbent 距 2.25×/2.21×。**现状即 +0.76 tok/s（702.7 µs = 2.28%）**；调到 1.3× 累计
   **1 148.7 µs = 3.72% = +1.25 tok/s**；调满新尺上限 **2 759.7 µs = 8.9% = +3.18 tok/s**（未必可达）。
   *（v4 算术更正：本行原写 +0.87 / 1 426 µs = 4.62% = +1.5 / +2.9。tok/s 一律用精确式
   `32.4/(1−µs/30860)`；1.3× 目标时间 = 78.99/1.3 与 74.14/1.3 ⇒ 收益 = 48×18.23 + 16×17.11
   = 1 148.7 µs，原 1 425.9 由本报告自己的目标时间反推不出来。发现于 #20-P2 计划评审 P0-5/P0-6。）*
3. **宽 P2（选项 C）前提削弱（v3 复核维持）**：大 K 两族的原型距新尺 1.82×（17408，
   incumbent 1.43×）与 4.40×（8704，incumbent 3.04×）——17408 上 incumbent 已相当接近新尺，
   8704 族 5.3 waves/CU 的 occupancy 短板是可见输因，但反超需先追平的差距更大了。
4. **L2 验收判据必须按产线基线重标定（本轮最重要的新事实）**：对 fp64 参考的 ULP 距离，
   **V3 原型 RMS = 0.024–0.027 ULP（MAX 1）——以 18× 余量通过 spec L2-c 的 0.5 ULP 门**；
   而 **incumbent（现产线 ExLlama）RMS = 69–219 ULP（MEAN 6.2–8.5，MAX 至 14 828）**——
   0.5 ULP 门按原文连产线内核都要拒。⇒ ① 6.3e-4 的旧读数纯属 clamp 放大假象，V3 数值
   **不是** A 的风险项；② 真正的 L2 门应写成"≤ incumbent 基线的若干分之一"，V3 比产线
   干净 3 个数量级。
5. **op/weight 作为主 KPI 退役**：设计的 4.25-4.36 op/weight 本就标定在"VALU 天花板 ≈ 字节
   地板"上，而字节地板已被证伪 ⇒ 该指标只剩"是否超预算 10%"的记录价值。**有效分母** =
   各形状探针最优时间（下表）。

- 标量探针（v2 的尺）确被证实 MLP 不足：三变体对比为 scalar 265–600 GB/s vs
  **mlp 387–597** vs **x4 349–702**（x4 在大 N 形状最优、mlp 在 N=5120 形状最优——
  x4 需 N/4 对齐 lane 映射，N=5120 时 1280 int4/行反而降低每 wave 覆盖）。
  v2 以 scalar 为尺得出的"原型 1.55×/2.76×"**低估了天花板**，本表已全部重算。
- incumbent 用**双缓冲轮换**重测（评审 P0-3）：与单缓冲差异 ≤2%，(3072,5120) 反而略慢
  ⇒ 该族是真实落败（v1 的 752 µs 分派收益因此修正为 702.7，见收益表）。
- op_per_weight：**未测得**（且按 P0-2 已无判别力）。VGPR：4 次提取失败 + unroll {1,2,4}
  时间不变 ⇒ 降为次要项。
- V2 数字（评审 P1-3 补）：rows.json 里 V2 最优 graph µs 按形状 = 122.4 / 232.9 / 95.5 /
  89.5 / 58.7，全输给 V3 —— LUT 的 bank-conflict 代价如预测存在，但值没到 kill 级。
- V1 vs V3 的归因（评审 P1-1 修正采纳）：**逐字去偏 ≈20 条/字（pair 循环内 5 条 ×4）是 V1
  的最大项**，butterfly 摊到每字仅 ~1 条——v1 报告把两项量级排反了。**V1 判死的主因是噪声**：
  随机 x 3.2e-3 = **3.3 fp16 ULP，超 spec L2-c 0.5 ULP 门 6.6 倍**（而 37 ops/word ≈ 4.63
  op/weight 只超预算 6%，成本是次因）⇒ P2 若继续必须走无偏提取（LUT 28 ops/word 或 cvt 路径）。

## 作废与未测清单（G5 合规，补齐评审 P1-3/P1-4）

- 171 行有效数据（rows.json）：V1 55 行、V2 55 行、V3 61 行；无组合因接线门被刷掉
  （门重构后 one-hot 全过 1.22e-04）；被 `(K/G)%sk` 过滤的组合 = K=5120 排除 sk=16、
  K=3072 排除 sk=16、K=8704 排除 sk=16（68 不整除）、17408 同 40。首版内核的
  `kper` 截断会**静默丢尾**，已加 `TORCH_CHECK` 整除断言。
- 首轮扫参（流修复前）171 行图计时**全部作废**（回放未执行内核）。
- 热回退：无（每形状 clock_status 回显 `8: 1700Mhz * 2: 1000Mhz *`，温度 41-58°C）。
- dot2 issue 速率：按 MI50 官方规格（FP16 26.5 / FP32 13.3 TFLOPS ⇒ packed=2×）离线定案：
  **dot2 占 1 issue slot 做 2 个 weight**，与设计 4.36 预算自洽 ⇒ 该待办关闭（评审漏 8）。
- eager vs graph：JSON 两列都有，eager 普遍比 graph 快 8-10%；选型按交付默认（graph）口径。

## 给 P2 的取舍（基于重标定后的尺）

- **选项 A（窄 P2）**：8192/7168 两族、V3 结构、把 1.55× 收向 load-only。现实预期
  **+1.2~1.6 tok/s**，天花板 +2.5。工程代价：dispatch 白名单 + 一族内核进镜像（评审漏 5）。
- **选项 B（不做 P2）**：人力转 #23 FP8 KV / #21 attention。
- **选项 C（宽 P2）**：**前提已按评审预判削弱**——8704 族的内核距自己天花板 2.76×，
  比 incumbent 的 1.91× 远；反超必须先解释并消除那 0.85× 的结构差，而 load-only 数据
  说明其中没有"白捡"的部分。

## §F 响应（评审联网核实补记后的修订；**v3 又升级了本节的两处**）

**BW 四方锚点**（评审 F4 新增 P0 的处置）：

| 锚点 | GB/s | 说明 |
|---|---|---|
| AMD 官方峰值 | 1024 | 硬上界 |
| 本机 clpeak global read | ~766（评审引既有实测） | 线性读 |
| torch.sum 整缓冲（本工作 G3 重测） | **813.8** | 线性读、只计 numel×2 |
| 标量 load-only（v2 曾用） | 272–600（按形状） | **4 B/lane 无展开 ⇒ MLP 不足，被 v3 证伪** |
| **mlp / x4 探针（v3 新尺）** | **387–702**（按形状） | 同模式的真实上限 |

⇒ v1 的"距字节地板 2.0–5.9×"混入了三个误差源：BW 标定 80–91% of peak 的可疑高速率、
地板漏形状项、以及 v2 拿 MLP 不足的标量探针当尺。**v3 主尺 = mlp/x4 探针最优**（每形状
实测，见主表），字节地板与标量探针列仅存档。

**VGPR：4 次尝试未打通，记录在案防重试**（评审 F3 的命令是下次起点）：
`llvm-readelf -n/--arch-specific` × {`.so`, `.cuda.o`} 全空；`--cuda-device-only` 重编出
`p1_dev.o`（63 KB）后同样读不出（疑仍为 bundle 或 MsgPack 解码未启用）。
~~降级理由：unroll {1,2,4} 时间逐位相同~~ **该理由已被评审 P0-2 撤回**（u=1/2 在 FOR 宏里
都映射到 16，是同一二进制重复计时；且 V3 的 `raw = dot2(raw,…)` 是 4×UNROLL 级串行链，
真 unroll 也测不出）⇒ VGPR/occupancy 恢复为"未测、待 `-Rpass-analysis` 路径"。
多条累加器（`raw[UNROLL]` 打散链）列为 **V3 最可能的改进点**（评审漏 2）。

**waves/CU（评审漏 2 与 P1-1 修正，最优配置；注意 3072/8704 是 K，N 都是 5120）**：原型
grid=(N/64)×splitK ⇒ 17408/sk8 = **36.3**、8704/sk4 = **5.3**、8192/sk8 = **17.1**、
7168/sk8 = **14.9**、3072(N=5120)/sk8 = **10.67**（incumbent 32–181，每 wave 固定 4 KB
权重）。8704 族的 5.3 waves/CU 与其"距探针尺 4.40×"吻合——occupancy 不足是它输的可见
原因之一；而 incumbent 同族也有 3.04× ⇒ 反超空间存在但要先吃掉这段差距。

**F1 采纳**：dot2 与普通指令同发射率（1 slot/2 weights）经三重交叉校验（CLRX timings、
官方 26.5/13.3 TFLOPS、6.624e12 lane-op/s）⇒ 设计 4.36 预算的**地基**正确，
错的只是它的数值噪声声明与没算进的实现项（去偏 ≈20 条/字等）。

## 遗留未闭合

1. ~~V3 送 L2 判据~~ **已测（本轮 #1）**：V3 RMS **0.024–0.027 ULP**（MAX 1），以 18× 余量
   通过 spec L2-c 0.5 ULP 门；v2 里 6.3e-4 的读数是 clamp 放大假象。**但 incumbent 自己
   RMS 69–219 ULP ⇒ 0.5 ULP 门按原文连产线内核都拒，L2 门须按产线基线重标定**（评审
   P1-7 的"否决权"以"判据重标定"收场）。
2. VGPR 未测得（4 次尝试见 §F 响应）——~~unroll 不敏感~~ 该证据被 P0-2 撤回（u=1/2 是
   同一二进制；V3 raw 是串行链）⇒ 恢复为"未测、待 `-Rpass-analysis`"；多条累加器列为
   V3 最可能的改进点。
3. #20-P0 桶表在交付时钟下的重跑仍未做（P0.5 遗留）——本报告的 incumbent 20 898 µs/token
   来自单卡微基准（1700 锁定），**不是**实机 TP2 桶表（评审漏 4）⇒ 收益百分比的置信度
   受此限制（评审 P1-8）。
4. 报告的 smoke 410 µs 与 BEST 115 µs 的落差（评审 P1-11）：smoke 用的是 V1 sk1/u8
   （单 chunk、无 splitK），BEST 是 V3 sk8/u4 —— smoke 只验证"图回放真的执行了内核"，
   不代表量级。
5. 探针未读 scales/qzeros（评审漏 5）：主流量相同但非 100% 相同访问（元数据 3.9%）；
   split-K 中间写流量 sk=8 最大形状 557 KB（占读 1.2%）——量级可忽略，列此存证（漏 6）。
6. kill 判据原文引用（评审漏 7）：spec 风险表"kill 判据：P2 结束时 L1 无任何形状 >1.1× →
   停投"。本报告"非 kill"指的是**该判据未被触发**（已有两族 >1.1），并非"达标"。
